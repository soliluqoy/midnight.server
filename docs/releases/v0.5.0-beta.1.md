# Midnight v0.5.0-beta.1 — native suite prerelease

This is a **GitHub prerelease**, not a stable release or an npm publication. It targets **Pi 1.2.0**, **Node.js 22.19+**, and Git on PATH. Pi loads the TypeScript source directly: there is no JavaScript compilation/build step.

## Included

- Native context management: editable `LIVE_CONTEXT.md`, branch-local projections/history, context viewer, budget reminders, overflow withholding, annotation and exact-source recall tools, and portable steering.
- Native checkpoints/rewind: asynchronous bounded Git snapshots, read-only coverage preview and explicit restore confirmation, conversation/files choices, scoped worktree/index restoration, redo backups, recovery journals, session-specific retention, and explicit legacy checkpoint metadata import.
- Shared service ownership and branch-local configuration. Overlapping native services pause when external CLM or rewind commands/tools are detected; legacy aliases are registered only when safe.
- Existing Midnight panels, explorer, theme, compact tools, titles and telemetry, plus clarification questions and evidence integration.
- Optional Chrome DevTools MCP adapter, disabled by default and explicitly connected to an existing loopback browser endpoint. Existing user MCP configuration retains precedence.
- Bundled portable context/checkpoint skills, upstream MIT licenses and source provenance. No personal credentials, connector skills, profiles or runtime configuration are copied.

New users do not need separate pi-clm or pi-rewind packages. Browser connections and external log uploads remain opt-in; normal model/API charges still apply when used.

## Install and migration

```sh
pi install git:github.com/soliluqoy/midnight.server@v0.5.0-beta.1
```

Inspect `pi list` first. Keep one Midnight source, and disable/remove only the external CLM/rewind entries you intend to replace. Restart Pi or run `/reload`, then check `/midnight status` and `/midnight doctor`. Midnight does not uninstall packages or rewrite user settings. Load the package directory, rather than only `src/index.ts`, to discover its theme and skills.

The attached `.tgz` is an npm-format extension package, **not an npm registry publication**. GitHub also supplies source ZIP/tar archives. `SHA256SUMS.txt` covers the attached extension package; extract the package to a directory if trying it as a local Pi package.

## Safety and limits

- Restores never reset Git HEAD or clean unrelated paths. They preserve distinct staged/unstaged layers and require a retained backup plus recovery journal.
- Checkpoints represent observed pending state, not exact authorship. Coverage can be incomplete: sensitive/unsupported paths and size bounds are shown rather than represented as clean state.
- Do not run concurrent Git/file operations during a restore. Guards detect stale state but are not a filesystem security sandbox. Local snapshots and saved transcripts may retain sensitive material.
- Snapshot limits: 10,000 paths, 10 MiB per file and 64 MiB raw capture. Unsupported/conflicted state is unavailable, not a clean snapshot.
- Native browser registration is not proof of a healthy connection. No automatic browser connections or log uploads are introduced.

## Validation and known release gates

Completed locally on the implementation before the version-only release preparation:

- `npm run check`: Biome and TypeScript passed.
- `npm test`: **137 cases; 136 passed, 0 failed, 1 skipped**. The Windows symlink test requires privileges unavailable on the validation host.
- Package dry-run: required native files, skills, steering, provenance and licenses present; no `node_modules` or `.artifacts` shipped.

Release preparation also checks formatting/types, creates the real package and checks its manifest and checksum. These packaging checks are **not** a fresh-install or interactive validation.

Still **unverified**, and required before declaring a stable release:

- Fullscreen keyboard, mouse, resizing and reload behavior.
- An isolated fresh single-package installation.
- Live browser connections and external-provider smoke tests. These were not run as release validation; paid checks require separate approval.

Source input hashes and attribution are in `docs/native-suite-provenance.json`, `NOTICE` and `licenses/`. Hashes identify the installed distributions inspected during integration, not independently verified published artifacts or upstream revisions.
